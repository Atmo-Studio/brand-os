# The token library contract

What a finished token library contains, which file is the source, and what is never edited by
hand. Read it before the first edit.

## The library

Everything sits in `brand/tokens/`. **Only `brand/tokens/src/` is edited.** Every other file is regenerated by
the build.

| Path | Status | Holds |
|---|---|---|
| `brand/tokens/src/brand.tokens.json` | Source | Brand: raw values in one mode. Color ramps, font families, weights, type sizes, leading, tracking, spacing, radius, stroke, shadow, duration, easing, content widths, breakpoints, the fluid range |
| `brand/tokens/src/intent.{brand}.tokens.json` | Source, one per sub-brand | Intent: the semantic ramps for one sub-brand, each pointing stop for stop at a Brand ramp. A single-brand library has one, named for the brand (`main` until it is renamed). Every Intent file holds the same names. A sub-brand is applied with `data-brand="{brand}"` |
| `brand/tokens/src/patterns.light.tokens.json` | Source | Patterns: the roles for the light theme, each color an alias to an Intent step |
| `brand/tokens/src/patterns.dark.tokens.json` | Source, only with a dark theme | The same roles, dark |
| `brand/tokens/src/patterns.{name}.tokens.json` | Source, only with a named theme | Roles for a ground that is not a color scheme, such as a dark section on a light site. Layered over the default theme, applied with `data-theme="{name}"` |
| `brand/tokens/src/tokens.resolver.json` | Source | The resolver: Brand, then the sub-brand's Intent, then the theme's Patterns. A context whose file is absent is skipped |
| `brand/tokens/src/pairs.json` | Source | Every foreground and ground pair to measure, with its floor, under `unpaired` every color role that decorates and why, and under `adjacent` the grounds that sit side by side when the default set does not fit |
| `tokens.css` | Generated | CSS custom properties: Brand on `:root`, a block per sub-brand and per theme, and a reduced-motion block |
| `tokens.json` | Generated | Every token resolved to its final value, per theme (per sub-brand and theme once there are sub-brands, keyed `brand/theme`), with the ramps, the scale, each role's Intent step and Brand step, and each name's layer |
| `tokens.js` | Generated | The same values as a JavaScript module |
| `tailwind.css` | Generated | A Tailwind v4 theme carrying the Patterns roles (never a ramp), the named spacing steps (`p-gutter`, `py-section`), the content widths (`max-w-content`, `max-w-prose`) and the breakpoints as values (`md:`) |
| `fonts.css` | Generated, only when a family lists font files | `@font-face` rules |
| `figma.json` | Generated | The payload a Figma sync pushes |
| `figma-push/`, `figma-parity.js`, `figma-parity.md` | Generated, only when syncing to Figma | The push scripts, the parity check and its report |
| `contrast.md` | Generated by the check | Every pair measured, in every theme |
| `package.json` | Written once from the starter | Name, version and exports, so a codebase can install the folder |
| `scripts/` | Copied from the starter | The build, the checks, the sheet. Refreshed from the starter whenever they differ from it: `brand-library` compares them first, since a check run by an old copy passes what the current one fails. A fix made for one brand is kept as a diff beside the library |

The build also writes outside the folder, when the files exist: the frontmatter and motion table of
`brand/DESIGN.md`, and `brand/standards.html`.

The source follows the Design Tokens Format Module 2025.10 (Design Tokens Community Group, 2025).
Two departures, both recorded in the files: tracking is a number read as `em`, and a typography
role's `lineHeight` points at a pixel leading token.

Extensions, all under `$extensions["brand-os"]`:

| Key | On | Does |
|---|---|---|
| `fluid` | A dimension: a `font-size` step, `spacing.gutter`, `spacing.section` | `{min, from, to}` in pixels. The build writes a `clamp()` that grows from `min` at `from` to the token's value at `to`. `from` and `to` default to `viewport.min` and `viewport.max`, so every fluid value grows across one range |
| `alpha` | A shadow, or a color that aliases another color | The opacity of a shadow whose color aliases a ramp step, or of a veil or scrim: `patterns.color.scrim` aliasing an Intent ink with `alpha: 0.4`. A color with its own `alpha` is written out, since `var()` cannot carry an opacity |
| `textTransform` | A typography role | A case the role is always set in |
| `fontFeatureSettings` | A typography role | OpenType features, such as `"tnum" 1` for tabular figures. Built to `--type-<role>-font-feature-settings` and applied by the sheet |
| `fontStretch` | A typography role | A width, such as `75%`. Built to `--type-<role>-font-stretch`. The family's file entry names the range it covers with `stretch` |
| `files` | A font family | `[{src, weight, style, stretch}]`. The build writes `fonts.css`; `weight` and `stretch` take a range (`"400 700"`, `"75% 100%"`) for a variable font |
| `reduced-motion` | A duration | The value it takes under `prefers-reduced-motion`. Feedback durations carry their own value |
| `keep` | An Intent ramp or a Patterns role | Where it is used outside the brand folder, such as a product's codebase. The audit counts it as used |

## Layers

Brand → meaning → application. Each layer holds one kind of token and switches one thing.

| Layer | Holds | Points at | Switches |
|---|---|---|---|
| **Brand** | Raw values, named for what they are | Nothing, or another Brand value (a shadow's color) | Nothing. One mode |
| **Intent** | What each value means: semantic ramps, stop for stop | Brand only | Sub-brand |
| **Patterns** | Where each meaning is applied: roles, and any component exception | A color at Intent; a group with no Intent (type, motion, elevation, logo) at Brand | Theme |

- **Work references Patterns only.** Brand and Intent exist so Patterns can point somewhere that
  changes in one place: a sub-brand repoints Intent, a theme repoints Patterns.
- **A sub-brand changes only Intent.** A branded house, whose sub-brands share the design language
  and system structure, is one library with an Intent file per sub-brand. Sub-brands use only the
  parent's Brand colors: a sub-brand's accent can differ, but it is a parent color. A house of
  unrelated brands gets a library per brand.
- **A theme changes only Patterns,** so a step number in Intent always means lightness.
- **Only color has an Intent layer,** and type does too where sub-brands differ in family. Spacing,
  radius, stroke and motion sit in Brand, and Patterns names them where materials need an applied
  name.

Published names drop the layer: `brand.color.stone.50` publishes as `--color-stone-50`,
`intent.color.neutral.50` as `--color-neutral-50`, and `patterns.color.text.primary` as
`--color-text-primary`. The check fails when two tokens would publish under one name, so a ramp is
never named for a role group such as `text` or `bg`, and a Brand ramp never takes an Intent name.

## Names

| Group | Brand | Intent | Patterns |
|---|---|---|---|
| Color | `color.{name}.{50…950}`, eleven steps, and `color.{name}` for a fixed color on no ramp. A color the brand specifies and names takes its brand name (`tidewater`); every other ramp a Tailwind-style hue (`stone`, `zinc`, `slate`, `gray`, `red`, `amber`, `green`) | `color.{accent, neutral, error, success, warning, info}.{50…950}`, and `action` where actions fill with another ramp than the accent. A fixed color joins its ramp: `color.neutral.paper` | `color.bg.*`, `color.text.*`, `color.border.*`, `color.accent.*`, `color.action.*`, `color.status.{state}.*` |
| Type | `font.family.*`, `font.weight.*`, `font-size.{step}`, `line-height.{step}`, `tracking.*` | Only where sub-brands differ in family | `type.{role}`, a typography composite |
| Spacing | `spacing.{n}`, where n counts base units, and two fluid steps: `spacing.gutter` (the page margin) and `spacing.section` (a section's own block padding) | none | none |
| Content width | `container.{content, prose}`: the widest a section's content runs, and the reading measure | none | none |
| Breakpoint | `breakpoint.{sm, md, lg, xl, 2xl}`, Tailwind's names, its defaults until the brand sets its own | none | none |
| Fluid range | `viewport.{min, max}`: where a fluid value is at its smallest, and where it reaches its full size | none | none |
| Radius | `radius.{none, xs, sm, md, lg, xl, 2xl, full}` | none | none |
| Shadow | `shadow.*` | none | `elevation.{raised, overlay}` |
| Stroke | `stroke.{hairline, focus, focus-offset}`, and one name per further weight the brand uses (`rim`) | none | none |
| Motion | `duration.{ms}`, `easing.{enter, exit, standard, linear}` | none | `motion.{feedback, component, layout}.{duration, duration-exit}`, `motion.easing.*` |
| Logo, when the brand has one | none | none | `logo.min-width` (a dimension, in px), `logo.min-height` (the height at that width, from the primary logo file's proportions, to the whole px), `logo.clear-space` (a plain number: the share of the logo's height kept clear on every side, `0.5` for half), `logo.min-clear-space` (that share of `logo.min-height`, to the whole px) |

- **The role inventory is a menu.** `roles.mjs` writes every role a brand might need, so a pair can
  be measured before work exists. Once the brand's materials exist, a Patterns role nothing uses,
  and an Intent ramp no role points at, come out: the audit lists them. Brand values may sit
  unused; they are the palette.

- **Depth without shadows.** Elevation is typed as a shadow, so a brand that marks depth by ground and
  hairline keeps `elevation.raised` and `elevation.overlay` as zeroed shadows (every length 0, alpha
  0) and records the method in `DESIGN.md`. The sheet draws the grounds and the stroke weights and
  leaves empty elevation rows out.
- **Layout names follow Tailwind v4's theme namespaces,** so a developer who knows Tailwind or a
  component library built on it reads them without a key: `--container-content` is `max-w-content`,
  `--breakpoint-md` is `md:`, `--spacing-gutter` is `px-gutter`. The Tailwind file adds the content
  widths beside Tailwind's own sizes rather than resetting them, since component libraries use
  `max-w-lg` and the rest.
- **A breakpoint is the one value work types.** A media query cannot read a custom property, so
  `DESIGN.md → ## Layout` states the breakpoint as its value beside its token, the raw-value scan
  allows a literal on a `@media` or `@container` line, and the Tailwind file writes breakpoints as
  values. Everywhere else a width is `var(--container-content)`, never `1200px`.
- **Margins and the display size are fluid,** clamped between `viewport.min` and `viewport.max`. No
  page types a size per breakpoint.
- **One word per concept:** `text`, `bg`, `border`. `accent` is the brand color. `primary` means the
  most prominent of its group and never the brand.
- **Every action role ships four states:** rest, hover, pressed and disabled, plus the focus ring.
  Each has a line in `pairs.json`. A disabled pair carries `exempt` with the reason.
- **The sheet needs these color roles,** and stops without them: `bg.page`, `bg.surface`,
  `bg.inverse`, `text.primary`, `text.secondary`, `text.inverse`, `text.on-accent`, `accent.bg`,
  `action.bg`, `action.text`, `border.subtle` and `border.default`.
- **Type steps in Brand are numbered from the base:** `font-size.0` is the base, `font-size.3` three
  steps up, `font-size.n1` one step down. Work uses the roles.
- **`spacing.n` is n base units.** With a 4px unit those match Tailwind's names and values. The
  Tailwind file sets `--spacing` to the base unit, so the two agree at any unit.
- **The Tailwind file resets each namespace it redefines,** so a utility the brand never defined
  stops resolving. The content widths are the exception, above.
- **One reference syntax per group, both checked.** Prose names a token in a group the DESIGN.md
  format holds as `{colors.x}`, `{typography.x}`, `{rounded.x}`, `{spacing.x}`, which its linter
  checks. Every other group (`stroke`, `container`, `breakpoint`, `viewport`, `motion`, `elevation`)
  is named by its published name in backticks, `` `stroke-rim` ``. `audit.mjs` resolves both against
  `tokens.json`, in every brand file, and fails a name that is not there.
- **A group added by hand before the contract named it** moves to the contract's name, with a diff
  that proves no value changed: `entry-states.md → AUDIT-AND-REBUILD`, step 7.

## The scripts

All run from `brand/tokens/` and print one JSON line. Each takes `--help`.

| Script | Does | Fails when |
|---|---|---|
| `brand/tokens/scripts/ramp.mjs` | Builds one eleven-step ramp from an anchor, on one lightness curve and one chroma curve every ramp shares. A pinned anchor bends its neighbours toward it. `--chroma` sets the curve's peak, `--tint` and `--cap` quiet the light end, `--match` shares another ramp's lightness | The anchor is not a six-digit hex |
| `brand/tokens/scripts/scale.mjs` | Builds the type scale, leading and spacing from a base, a ratio and a unit. Every step rounds to the nearest whole pixel, one rule; leading lands on the unit. Named spacing steps are kept | The base, the ratio or the reason is missing, or two steps round to one size |
| `brand/tokens/scripts/roles.mjs` | Writes a sub-brand's Intent ramps and a theme's Patterns roles, and adds their pairs. With `--brand` naming a second sub-brand, writes only its Intent. Replaces the starter's placeholder roles and ramps, and keeps the proportion | A named ramp does not exist, or the brand's own roles exist and `--force` is absent |
| `brand/tokens/scripts/build.mjs` | Regenerates every output. `--verify` writes nothing and compares | `--verify` finds a stale file |
| `brand/tokens/scripts/check.mjs` | Runs the eight checks and writes `contrast.md` | Any check fails |
| `brand/tokens/scripts/audit.mjs` | Scans prose or code for literals: colors, sizes, families, and in code weights, leading, tracking, and any spacing, size or radius length typed as a literal, even one equal to a token. It catches derived sizes too: a unitless length in script, a token multiplied in `calc()`. In prose it also flags a contrast ratio typed by hand, resolves every token name in braces or backticks, and fails a token named by its source path (`motion.feedback.duration`) with its published name. With no path it also reads every SVG under `brand/assets/` for live text, and, once `DESIGN.md` exists, lists every Intent ramp and Patterns role nothing uses | A literal is found, a token name resolves to nothing or is a source path, an SVG holds a `<text>` element, or a token is unused |
| `brand/tokens/scripts/outline.mjs` | Replaces live `<text>` in the brand's SVGs with outlined paths, set from the brand's own font files with HarfBuzz, so kerning holds. Reports each line's set width and ink, for a mark drawn to a line's width. Needs `npm install --no-save harfbuzzjs` once | A text names a family with no font file, a font file is not TrueType or OpenType, a `<tspan>` carries its own position, or harfbuzzjs is missing |
| `brand/tokens/scripts/diff.mjs` | Compares two builds, aliases resolved. `--rename` maps old names to new first, for a group moved to the contract's names | A resolved value changed |
| `brand/tokens/scripts/figma-push.mjs` | Writes the scripts that push `figma.json` into a Figma file | `figma.json` is missing |
| `brand/tokens/scripts/parity.mjs` | Writes the Figma parity check and reads its result | Figma differs from `figma.json` |
| `brand/tokens/scripts/sheet.mjs` | Renders the standards sheet, or review boards with `--draft` | The build has not run |

## The checks

1. An alias that does not resolve, or a cycle.
2. Two tokens publishing under one name.
3. A name present in one sub-brand or theme and missing from another.
4. A layer pointing past the layer below it: Intent at anything but Brand, a Patterns color at
   anything but Intent, a Patterns token of another group at anything but Intent or Brand. A raw
   value in Intent, or a raw color in Patterns. A Brand color sharing a name with an Intent ramp.
5. A pair in `pairs.json` under its floor: 4.5:1 for text, 3:1 for large text, marks and
   boundaries (World Wide Web Consortium, 2023).
6. A placeholder from the starter still in the source.
7. A color role in no pair and not listed under `unpaired`.
8. Two grounds that sit side by side under 2:1 against each other. Two dark fills that differ in
   hue alone read as one where they meet: a check that measures only text on ground passes them.
   With no `adjacent` list in `pairs.json`, the check measures every two of the main grounds and
   fills (the page, the inverse, the accent and action fills, and any ground the proportion names),
   skipping two roles on one step. An `adjacent` list replaces that default: `{ "a", "b" }`, with
   an optional `floor`, and `exempt` with the reason for two grounds that never touch. The 2:1
   floor is Atmo's own, set from a test kit where 1.37:1 read as one dark and 2.16:1 read as two.

`pairs.json` may also list `distinct` pairs: two roles told apart by color alone. The check measures
their distance under normal, deutan, protan and tritan vision and fails under a margin of 6, unless
the pair names a `carrier` such as a glyph or a label.

## Without Node

The library still gets built. It is not checked, and the user is told so.

Paths to `expertise/` below run from the Brand OS root.

1. Write `brand/tokens/src/` by hand to this contract. Compute ramps as `expertise/color/color-ramps.md`
   describes, and the scale as `expertise/typography/typescale.md` describes.
2. Write `tokens.css` by hand: Brand and Intent on `:root`, each Patterns role as `var()` of the
   Intent name it aliases, one block per theme and one per sub-brand.
3. Measure every pair in `pairs.json` with whatever contrast tool is at hand, and the main grounds
   and fills against each other at 2:1, and record the ratios in `contrast.md`.
4. Write in `brand/decisions.md` that the library was built without its scripts and has not passed
   the check. The first session with Node runs `node scripts/build.mjs && node scripts/check.mjs`
   and reconciles whatever differs.
