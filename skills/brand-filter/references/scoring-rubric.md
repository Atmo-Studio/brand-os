# Scoring Rubric
*Part of `brand-filter` · Load before scoring — Phase 2 step 4 and every improvement-loop re-score*

Scores are only useful if the same input would earn roughly the same score tomorrow. This rubric is the calibration: what each band means, what evidence a score requires, and how a claimed improvement is measured. It applies identically to the founder's input and to your own loop proposals.

---

## Scoring rules

1. **Score the idea as pitched, not the best version of it.** The improved version belongs in the improvement loop, not in the score. Inflating a 5 to a 7 because you can imagine the fix hides exactly the signal the filter exists to catch.
2. **Evidence per filter: at least two quoted knowledge-base lines.** Each score names the specific lines the input aligns with or fails against. A filter you can't evidence is unscored, never estimated.
3. **The band is the judgment; the decimal places the input within it.** Decide the band first from the anchors below, then position within it. Never pick a number and rationalize backward.
4. **Fatal band (0–3) overrides the average.** A single fatal filter is a red flag no overall score offsets. Name it as fatal in the presentation.
5. **Soft-evaluation check.** If every filter lands 8+ with no tension anywhere, re-check the input against the brand's negative space — the values' "doesn't mean" columns, the personality's "we are not" list, the visual hard don'ts — before presenting. Uniform praise usually means the evaluation went soft.

---

## The bands

| Band | Meaning | Evidence test |
|---|---|---|
| **0–2 · Contradiction** | Violates the brand's explicit negative space: a value's "doesn't mean," a "we are not" trait, a hard don't, or the positioning's named misframing | You can quote the line it violates |
| **3–4 · Invented connection** | Supporting it requires a story the knowledge base doesn't tell | No supporting quote exists; the nearest knowledge-base language is silent or argues against |
| **5–6 · Adjacent / generic** | Supportable, but any competent brand in the category could run it | Supporting quotes exist but prove nothing distinctive |
| **7–8 · Aligned** | Supported by knowledge-base language, no contradictions, competently on-brand | Multiple supporting quotes, zero negative-space hits |
| **9–10 · The dimension in action** | Could only come from this brand; it enacts the knowledge-base language rather than merely complying with it | The supporting quotes are load-bearing: remove the brand's specifics and the idea stops working |

## Per-filter anchors

What the low, middle, and top bands look like for each filter, keyed to the knowledge base's own structures.

| Filter | 2–3 | 5–6 | 9–10 |
|---|---|---|---|
| **Purpose** (11) | The connection requires a story you'd have to invent; the purpose statement doesn't recognize this work | Purpose-adjacent — connects, but it would connect for any brand in the category | The purpose statement in action; the idea makes "[Brand] exists to ___" more true |
| **Values** (12) | Enacts something a "This doesn't mean" column explicitly names | Values-neutral: violates nothing, expresses nothing | A top-priority value doing visible work — behavior, not a label |
| **Audience** (21) | Speaks to a different audience than any documented ICP — peers, investors, the industry | Relevant to an ICP in general, but not to their documented jobs or stuck points | Names a specific ICP's actual moment; the functional, emotional, or social job language fits it directly |
| **Positioning** (23) | Matches the "common misframing," or reads like one of the documented alternatives | Positioning-neutral filler; neither reinforces nor dilutes | Could only come from this brand; makes the positioning statement more true |
| **Personality** (31) | Sits in territory the spectrum marks as never-go, or the "we are not" list names | Right register, generic texture — professional but interchangeable | The personality summary made audible; specific and unmistakable |
| **Story role** (41) | The brand is the protagonist; the customer exists to validate it | The customer is present, but the brand still holds the insight and the credit | The customer's transformation carries the piece; the brand is the guide with a plan |
| **Voice** (42, copy) | Uses "we avoid" vocabulary, or matches a tone mode's "doesn't sound like" pattern | Clean of violations but voiceless; could be any brand's copy | Passes the vocabulary and tone mode, and reads unmistakably like the voice description |
| **Pillar fit** (43, copy) | Makes a claim no pillar supports, or contradicts one | Near a pillar, but without its proof points — the claim floats | Ladders to a named pillar, carries its proof, matches its channel expression |

Dimensions the knowledge base doesn't have yet make their filter **unscored**. The anchors only work against real knowledge-base language.

---

## Measuring improvement

The improvement loop's re-scores follow every rule above, plus:

1. **A band only moves with a named change.** For each filter that improved, state what specifically changed in the proposal and quote the knowledge-base line that now supports it. If you can't name what moved it, it didn't move.
2. **Report the delta per filter.** The presentation shows, for each filter: the original's band, the proposal's band, and the change that carried it. This is what makes the loop's claim of improvement checkable rather than asserted.
3. **Copy is scored as written.** When the proposal is or contains copy, write it per the Voice & Tone Guide first; the Voice filter scores the actual words, not the intention behind them.
4. **The 9+ bar is the band definition, not a number to reach.** A proposal earns 9–10 only if it passes the top band's evidence test: the brand's specifics are load-bearing. If five iterations don't get there honestly, present the best attempt with its real band and name the blocker.
